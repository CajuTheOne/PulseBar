# PulseBar — как устроен

Основной текст ниже описывает 1.x (состояние на 20.10.2026). Что изменилось в 2.0 — в следующем разделе;
где они расходятся, верен раздел 2.0.

## Версия 2.0 (30.10.2026)

Два процесса вместо одного:

| Процесс | Права | Что делает |
|---|---|---|
| `PulseBar.exe` (`src\PulseBar`) | обычные | строка, меню, датчики CPU/GPU/RAM, модуль Logitech, проверка обновлений |
| `PulseBar.Sensor.exe` (`src\PulseBar.Sensor`) | служба `PulseBarSensor`, LocalSystem | только температура CPU через PawnIO |

- **Канал.** Служба слушает `\\.\pipe\PulseBar.Sensor` (до 4 подключений — по строке на каждого вошедшего
  пользователя; вошедшим пользователям — чтение/запись, из сети — запрещено). Запрос — байт `T`, ответ — `float`
  температуры (NaN — нет данных), байт длины и состояние датчика в UTF-8 (`src\Shared\SensorPipe.cs`).
  В строке канал опрашивает отдельный поток (`CpuTempSensor.cs`): окно получает значение прошлого опроса и
  никогда не ждёт службу.
- **Температура Intel.** Модуль PawnIO `IntelMSR`, функция `ioctl_read_msr`: TjMax из `MSR_TEMPERATURE_TARGET`
  (`0x1A2`, биты 23:16), температура пакета = TjMax − биты 22:16 `IA32_PACKAGE_THERM_STATUS` (`0x1B1`).
  Модули `AMDFamily17.bin` и `IntelMSR.bin` — из релиза 0.2.11 namazso/PawnIO.Modules (LGPL-2.1).
- **Строка внутри панели задач** (`BarWindow.cs`). Дочернее окно `Shell_TrayWnd`: `WS_CHILD | WS_CLIPSIBLINGS`,
  `WS_EX_LAYERED | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`; дочерние layered-окна требуют в манифесте поддержку
  Windows 8+ (`app.manifest`). Положение — `SetWindowPos` в координатах панели, картинка — `UpdateLayeredWindow`
  без `pptDst`. Встраивание возможно, потому что строка больше не работает с правами администратора (UIPI).
  Форма `Overlay` теперь невидимое окно: таймеры, `TaskbarCreated`, `WM_SETTINGCHANGE`, `WM_DEVICECHANGE`, меню.
  После перезапуска Проводника строка создаётся заново. Если создать дочернее окно не удалось или пункт
  «Встраивать в панель задач» выключен — прежнее окно поверх панели с z-порядком из 1.x.
- **Автозапуск** — `HKCU\...\Run\PulseBar`, без прав; задачу Планировщика `\AI Tools\PulseBar` удаляет установщик.
  Пункт «Перезапустить с правами администратора» убран.
- **Обновления** (`Updater.cs`): `GET api.github.com/repos/CajuTheOne/PulseBar/releases` через 5 с после
  запуска (до 2.1.0-beta.5 — через минуту), раз в сутки и по кнопке «Проверить обновления»; берётся самый новый релиз (пре-релизы — если включены бета-версии) с файлом
  `PulseBar-Setup*.exe`; версии сравниваются по SemVer. Установка: скачать в `%TEMP%`, сверить размер и SHA-256
  (`digest` из GitHub), запустить установщик с `/SILENT /SUPPRESSMSGBOXES /NORESTART` и выйти; установщик
  перезапускает строку от имени пользователя.
- **Установщик** — Inno Setup (`installer\PulseBar.iss`), сборка — `build.ps1`, релизы — GitHub Actions
  (`.github\workflowselease.yml`).

## Версия 2.1 (31.10.2026)

- **Блоки по списку.** `Settings.Blocks()` — видимые блоки в заданном порядке (`blocks`, `show*`); `BarRenderer`
  считает ширину и рисует блоки циклом и запоминает их границы (`Blocks`) для подсказки.
- **Claude** (`ClaudeUsage.cs`): таймер раз в минуту на пуле потоков; берёт более свежее из истории приложения Claude и
  ответа `api/oauth/usage` (поддержаны оба формата ответа: `five_hour`/`seven_day` и массив `limits`); запросы к API —
  не чаще настройки и с `Retry-After`. Событие `Changed` → строка перерисовывается в своём потоке.
  Токен для API (2.4.0-beta.8) — вход самого приложения Claude (`Ai\ClaudeAppAuth.cs`): `config.json` →
  `oauth:tokenCacheV2`, шифр Chromium "v10" (AES-256-GCM), ключ из `Local State` под DPAPI текущего пользователя;
  берётся действующий токен с правом `user:profile` аккаунта, открытого в приложении. Файлы перечитываются, только когда
  `config.json` изменился; токен не продлевается и не записывается. Иначе — вход Claude Code, иначе — только история
  (её приложение не пишет, если окно расхода не открывали 24 часа).
- **Подсказка** (`TooltipForm.cs`): окно без фокуса и прозрачное для мыши; `BarWindow` следит за мышью
  (`TrackMouseEvent`), `Overlay` через 0,45 с показывает подсказку над блоком; история — последние 60 с замеров.
- **Окно настроек** (`SettingsWindow.cs`, WPF) — в отдельном процессе (`SettingsProcess.cs`), см. SETTINGS.md.
  Строка общается с ним через `settings.json`, `logitech.json`, `status.json` и сообщения `PulseBar.SettingsChanged` /
  `PulseBar.LogiReload` / `PulseBar.LogiRestore` / `PulseBar.LogiBackup`,
  отправленные прямо в её скрытое окно (дескриптор — аргумент запуска).
- **Переводы**: `L.T` ищет в таблице 1.x, затем в `L.Strings2.cs` (строки 2.x), затем в дополнительных ru/uk, иначе English.

## Версия 2.3 (31.10.2026): модуль Logitech

Пока строка запущена, клавиатура G915/G913 всегда в режиме PulseBar (HID++ `0x8100` режим 2); при выходе, сбое
и запуске G HUB — своя память (режим 1) на профиле с тем же номером. Слои (`src\PulseBar\Logi\`):

- `HidppLink` — канал HID++ одного приёмника или провода: один поток-владелец пишет в устройство по очереди,
  программный id 2–15 по кругу, повторы при «занято» и без ответа; уведомления (id 0) и подключения (регистр 0x41) —
  в отдельном потоке событий; ответы на чужие запросы (G HUB, служба Logitech LampArray) — событие `Foreign`.
- `LogiDevice` — устройство на канале: карта функций, имя, вид, заряд.
- `LogiKeyboard` — настройка (режим 2, перехват G-клавиш, программное управление подсветкой `0x8071` fn5 = 03,
  таблица эффектов `0x8071` по зонам для окна настроек; номера клавиш по карте `0x8081` и раскладке `0x4540`), кадр
  подсветки цветами по клавишам `0x8081` (эффекты `0x8071` в режиме PulseBar G915 не рисует), яркость `0x8040`,
  лампочки M `0x8020`; отправляет только разницу с уже применённым.
- `KeyEdges` — нажатия G/M/MR по маскам, только фронт; из нескольких M в одном сообщении — левая.
- `OnboardMemory` / `OnboardSector` / `OnboardPlan` — память (формат 4, сектор 255): чтение, запись с обратным
  чтением, CRC, сборка профилей M1–M3 из `logitech.json`.
- `LogiService` — один поток службы: все изменения через очередь, сверка клавиатуры с желаемым состоянием (профиль по
  программе или вручную, приглушение, экран, блокировка, сон, заряд) после каждого события и раз в 20 с; запись памяти
  через 4 с после изменения профилей; перерисовка после чужой записи подсветки (не больше 5 раз в минуту).
  Событие яркости `0x8040` fn0 приходит и на каждую свою запись (тем же значением), и от кнопки, и когда клавиатура
  гаснет сама: нажатием считается только смена, которой не было в записях; 0 % не с шага 12 % — «погасла сама», в
  профиль не идёт, подсветку зажигает следующий ввод (`LastBrightness`, `_darkSince`).
  Мыши других фирм (`OtherMice`): заряд Razer по протоколу Synapse (отчёт 91 байт, класс 7), до трёх попыток; не
  прочитан ни разу — снова через 30 с; прочитанный не теряется при пересканировании; в журнал — только смена итога.
  Окружение (`LogiEnv`) подменяется в тестах моделью G915 (`tests\PulseBar.Tests\FakeG915.cs`).
  Клавиатура и мышь целиком (2.4.0-beta.8): `LogiConfig.KeyboardOn` / `MouseOn` — выключено: не открываются каналы
  и не ищутся устройства этого вида (оба выключены — HID++ не открывается совсем), клавиатура возвращается своей памяти.
  `KeyboardDevice` / `MouseDevice` — выбор кнопкой «Определить»; Id: `logi:<PID канала>:<номер на приёмнике>`,
  `hid:<VID>:<PID>`. Служба отдаёт окну `Found` (все найденные устройства с `Support`: full / battery / windows и
  функциями HID++) через `status.json`; спящее устройство узнаётся по `devices.json` (запоминается при каждом подключении).
  Клавиатуры других фирм (`OtherMice.FindKeyboards`, HID 1/6) — только для списка: им — настройки Windows.
  Окно показывает разделы «Подсветка» и «Клавиши G» по функциям клавиатуры; пока функции неизвестны — всё.

## Общая схема

Один процесс .NET 9 (WinForms), без сторонних библиотек: всё остальное — прямые вызовы Windows API.
Процесс запускается задачей Планировщика при входе в Windows с наивысшими правами (нужны только для
температуры CPU), рисует строку поверх свободного места панели задач слева от области уведомлений и раз
в секунду обновляет значения.

| Файл | Что внутри |
|---|---|
| `Program.cs` | Точка входа: один экземпляр (mutex), ключи командной строки, перехват необработанных ошибок в журнал, EcoQoS |
| `Overlay.cs` | Окно поверх панели задач: таймер, расположение, z-порядок, скрытие в полноэкранном режиме, меню, автозапуск |
| `BarRenderer.cs` | Раскладка и отрисовка строки (одна строка / две строки с вертикальными подписями), палитра |
| `Sensors.cs` | Датчики: загрузка CPU, температура CPU (PawnIO), GPU и VRAM (D3DKMT), RAM |
| `Native.cs` | Все P/Invoke: user32, gdi32 (в т.ч. D3DKMT), kernel32, pdh, cfgmgr32, dwmapi |
| `Settings.cs` | Настройки (`settings.ini`, формат key=value) и журнал |
| `ThresholdsForm.cs` | Окно «Пороги» |
| `DarkMenuRenderer.cs` | Тёмная тема контекстного меню |
| `Strings.cs` | Переводы интерфейса (11 языков) |
| `Autostart.cs` | Задача Планировщика `\AI Tools\PulseBar` |
| `Resources/AMDFamily17.bin` | Модуль PawnIO для чтения регистров AMD Zen (9300 байт, взят из LibreHardwareMonitorLib 0.9.6) |
| `install.ps1` | Установка/обновление/удаление |

## Окно на панели задач

- Отдельное окно верхнего уровня: `WS_POPUP`, `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE`.
  Нет в Alt+Tab и на панели задач, не забирает фокус при клике.
- Кадр рисуется GDI+ в DIB-секцию 32 бит с premultiplied alpha и выводится `UpdateLayeredWindow` —
  попиксельная прозрачность, текст сглажен по серой шкале (ClearType на прозрачном фоне невозможен).
- Фон заливается цветом с альфой 1 (невидимо), чтобы правый клик ловился по всей площади, а не только по буквам.
- Положение: правый край = левый край `TrayNotifyWnd` (область уведомлений) минус «отступ от трея»;
  высота = высота `Shell_TrayWnd`; масштаб = `GetDpiForWindow(Shell_TrayWnd) / 96`. Процесс Per-Monitor-V2 DPI aware.
- Поддерживается только горизонтальная панель на основном мониторе.

### Цикл обновления

1. `SetCoalescableTimer` с интервалом из настроек (по умолчанию 1000 мс) и допуском 10 % (не больше 100 мс):
   Windows может объединять пробуждения с другими таймерами.
2. `Tick`: если строку показывать не нужно (полноэкранное приложение, скрытая панель) — окно прячется,
   датчики **не опрашиваются**. Иначе — опрос датчиков, проверка темы раз в 10 с, расчёт положения.
3. Перерисовка только если изменился «отпечаток» показываемых значений (округлённые числа + версия настроек + тема).
4. `UpdateLayeredWindow` при перерисовке или сдвиге, затем проверка z-порядка.

### Z-порядок (почему строка не пропадает и не моргает)

Строка — отдельное окно «поверх всех», как и сама панель задач. Когда пользователь кликает по панели, Проводник
поднимает её наверх, и она закрывает строку. Поэтому:

- `EnsureAboveTaskbar` проходит по окнам выше строки; если среди них панель задач — строка переставляется
  **сразу над панелью** (`SetWindowPos` после окна, стоящего над панелью), а не на самый верх. Иначе строка
  перекрывала бы своё же меню, подсказки и другие окна «поверх всех» — меню моргало.
  Если окно над панелью не «поверх всех», используется `HWND_TOPMOST`, чтобы не потерять этот статус.
- `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` — при смене активного окна позиция проверяется сразу, без опроса датчиков.
- После смены активного окна и после закрытия меню — повторная проверка через 120 мс (панель может подняться позже события).
- Пока открыто меню, строка не перерисовывается, только держится над панелью.

Альтернатива — встроить окно внутрь панели задач, как это делает Claude Code Usage Monitor. Разбор — в
[COMPARISON.md](COMPARISON.md).

### Когда строка прячется

- Полноэкранное приложение: активное окно на мониторе панели задач покрывает весь монитор
  (кроме рабочего стола `Progman`/`WorkerW` и самой панели). Отключается пунктом меню.
- Автоскрытие панели: видимая часть панели меньше половины её высоты (реакция — до одного тика).
- Перезапуск Проводника: окно панели ищется заново по `IsWindow` и по сообщению `TaskbarCreated`
  (разрешено через `ChangeWindowMessageFilterEx`, т.к. процесс работает с правами администратора).

## Датчики

| Показатель | Как читается | Стоимость за обновление |
|---|---|---|
| Загрузка CPU | PDH `\Processor Information(_Total)\% Processor Utility` (как в Диспетчере задач), ограничение 0–100; запасной вариант — `GetSystemTimes` | ~0,1 мс |
| Температура CPU | PawnIO, регистр SMN `0x00059800` (Tctl/Tdie) | один IOCTL, ~0 мс |
| Загрузка GPU | D3DKMT, время работы движков видеокарты | ~0,5 мс на движок |
| Температура GPU | D3DKMT `KMTQAITYPE_ADAPTERPERFDATA` | ~0,001 мс |
| Занятая VRAM | D3DKMT, статистика сегментов памяти | ~0,001 мс на сегмент |
| RAM | `GlobalMemoryStatusEx` | микросекунды |

Итого около 1,9 мс за обновление (замер 13.10.2026).

### Температура CPU (AMD Ryzen, PawnIO)

- Драйвер PawnIO (подписанный, ставится отдельно) должен быть установлен; WinRing0 не используется
  (его блокирует Defender).
- Устройство `\\?\GLOBALROOT\Device\PawnIO`. Загрузка модуля — IOCTL `0xA1B22084` с содержимым `AMDFamily17.bin`.
  Вызов функции — IOCTL `0xA1B22104`: на входе 32 байта имени функции (`ioctl_read_smn`) и 8 байт аргумента
  (адрес `0x59800`), на выходе 8 байт значения.
- Формула как в драйвере Linux `k10temp`: `t = (v >> 21) * 0.125`; если установлен бит 19 или биты 17..16 = 3,
  вычесть 49 °C.
- Процессор определяется через CPUID: производитель `AuthenticAMD`, семейство ≥ 17h (Zen). Intel не поддерживается.
- Без прав администратора драйвер возвращает ошибку 5 — в меню показывается причина и пункт
  «Перезапустить с правами администратора» (через задачу Планировщика, без окна UAC).

### GPU (D3DKMT — источник Диспетчера задач)

- Адаптеры: `D3DKMTEnumAdapters2`, идентификаторы — `KMTQAITYPE_PHYSICALADAPTERDEVICEIDS` (31),
  `Microsoft Basic Render` (VEN 1414) пропускается. Автовыбор — адаптер с наибольшей собственной памятью
  (`KMTQAITYPE_GETSEGMENTSIZE`, 3), т.е. дискретный. Имя — из диспетчера устройств (cfgmgr32).
- Загрузка: `D3DKMTQueryStatistics` типа NODE (5) → `RunningTime` (100 нс) каждого движка; загрузка = максимум
  по движкам от прироста за интервал (как в Диспетчере задач).
- Каждый такой запрос стоит ~0,5 мс, а у RTX 4090 Laptop 14 движков, поэтому они отбираются по
  `KMTQAITYPE_NODEMETADATA` (25): 3D и вычисления (сюда же попадает CUDA) — каждое обновление; видеодекодер,
  кодер, видеообработка — раз в 4 обновления, пока простаивают; копирование, оверлей, безопасность и прочее — не опрашиваются.
- Температура: `KMTQAITYPE_ADAPTERPERFDATA` (62), поле `Temperature` в десятых долях °C.
- Спящая дискретная видеокарта: состояние питания читается из `DEVPKEY_Device_PowerData` (cfgmgr32). Если не D0 —
  температура не запрашивается, вместо неё показывается «sleep»/«сон».
- VRAM: при открытии адаптера отбираются сегменты с `Aperture == 0` (собственная память); каждое обновление —
  сумма `BytesResident` по ним, делённая на `DedicatedVideoMemorySize`. Совпадает с «Выделенной памятью GPU»
  в Диспетчере задач.
- Раскладки структур (x64) сверены с `d3dkmthk.h` из Windows SDK 10.0.26100 компиляцией пробной программы:
  `D3DKMT_QUERYSTATISTICS` — 808 байт, результат с 24, параметр (NodeId/SegmentId) — 800;
  `NbSegments` +0, `NodeCount` +4; в сегменте `BytesResident` +16, `Aperture` +40;
  `D3DKMT_ADAPTER_PERFDATA` — 64 байта, `Temperature` — 56; `D3DKMT_NODEMETADATA` — 78 байт.

### Сверка показаний (на этом ноутбуке, ASUS ROG Zephyrus Duo 16 GX650PY)

| Что | PulseBar | Эталон |
|---|---|---|
| Температура GPU | 54,7 °C | nvidia-smi 55 °C |
| Загрузка GPU | 96 % (движок 3D) | счётчики «GPU Engine» Диспетчера задач — 91 %; nvidia-smi 99–100 % |
| VRAM | 6099 МБ | счётчик «GPU Adapter Memory\Dedicated Usage» — 6099 МБ; nvidia-smi 6090 МиБ |
| Температура CPU | 70 °C при 16 % загрузки | правдоподобно для Ryzen 9 7945HX; с HWiNFO не сверялось |

Загрузка GPU сверялась в разные моменты под переменной нагрузкой (python и llama-server на видеокарте),
поэтому цифры близки, но не равны; источник — тот же, что у Диспетчера задач.

## Отрисовка

- Два вида: «одна строка» (`CPU 6% 70°C │ GPU … │ VRAM 38% 6.1 GB │ RAM 61% 38.4 GB`) и «две строки,
  вертикальные подписи» (повёрнутая подпись │ полоска загрузки │ загрузка над температурой/объёмом).
  Порядок блоков: CPU, GPU, VRAM (можно скрыть), RAM.
- Шрифты (px при 100 %, умножаются на масштаб DPI и размер текста 0,88 / 1 / 1,15):

| Элемент | Одна строка | Две строки |
|---|---|---|
| Подписи CPU, GPU, RAM | 11, Segoe UI Semibold | 12, вертикально |
| Подпись VRAM | 11 | 10, вертикально |
| Проценты и температура | 13,5, Semibold | 12,5, Semibold |
| Объём (GB) | 12, Segoe UI | 11,5, Segoe UI |

- Полоска загрузки: ширина 5 px при 100 % (`round(4.5 × масштаб)`, целые пиксели), высота 62 % высоты панели,
  заливка снизу по проценту, цвет по порогу.
- Вертикальные подписи: текст рисуется горизонтально с хинтингом (`AntiAliasGridFit`), картинка поворачивается
  попиксельно `RotateFlip(Rotate270FlipNone)` и ставится по целым координатам — так она чёткая, как обычный текст.
  Готовые картинки кэшируются.
- Разделители: только в одной строке (1 px, 42 % высоты). В двух строках — промежуток «расстояние между блоками».
- GDI+ центрирует строку по полной высоте, а цифры визуально выше — центр сдвигается на 0,065 размера шрифта вверх.
- Палитра для тёмной и светлой панели (`SystemUsesLightTheme`): норма зелёная (`#4ADE80`) или синяя (`#60A5FA`),
  повышенная `#FBBF24`, перегруз `#FF5C5C`, нет данных — серый. Числа объёма — `38.4 GB` всегда с точкой.

## Меню и окно порогов

- Правый клик: окно делается активным (`SetForegroundWindow`), иначе меню не закрывалось бы кликом мимо.
  После закрытия фокус возвращается окну, где он был (если пользователь сам не ушёл в другое).
- Тёмное меню — собственный `ToolStripProfessionalRenderer`: точки у переключателей, галочки у флажков.
- Окно «Пороги»: для шести параметров (загрузка/температура CPU, загрузка/температура GPU, VRAM, RAM)
  значения «жёлтый от» и «красный от»; красный всегда выше жёлтого. Тёмный заголовок через DWM.
- Двойной клик по строке — Диспетчер задач.

## Локализация

`L.T("English text")` — ключом служит английский текст, он же значение по умолчанию. 11 языков: English (по умолчанию),
Русский, Українська, Deutsch, Français, Español, Português, Italiano, Polski, 中文, 日本語. У пункта «Language» в
других языках в скобках стоит «(Language)», чтобы найти его, не зная выбранного языка. Переводы, кроме русского и
украинского, сделаны без носителей языка.

Глобализация .NET — через системный NLS (`System.Globalization.UseNls`). Режим `InvariantGlobalization` нельзя:
WinForms при смене раскладки клавиатуры создаёт `CultureInfo` по её коду, и в этом режиме программа падала
при правом клике (`1033 (0x0409) is an invalid culture identifier`).

## Автозапуск

Задача Планировщика `\AI Tools\PulseBar` (XML, создаётся `PulseBar.exe --autostart on`):
триггер — вход пользователя с задержкой 10 с; `RunLevel = HighestAvailable` (права администратора без UAC);
не останавливается от батареи; без ограничения времени работы (`PT0S`); приоритет 5; повторный запуск игнорируется.

## Лёгкость и производительность

- Замеры установленной версии: 0,16–0,4 % одного ядра (≈0,01 % всего процессора на 32 потоках), 16–18 МБ
  собственной памяти, 7 потоков.
- Первая версия опрашивала все 14 движков GPU и тратила 8 % ядра; после отбора движков — 0,39 %.
- Приёмы: ReadyToRun (меньше JIT при старте), `TieredPGO=false`, EcoQoS (`SetProcessInformation`),
  таймер с допуском, перерисовка только при изменении, датчики не опрашиваются, пока строка скрыта,
  после старта, меню и диалогов — `GC.Collect` и `SetProcessWorkingSetSize(-1, -1)`.
- Фоновый GC оставлен включённым: с ним бюджет поколения 0 не больше 6 МБ, без него может вырасти примерно до 200 МБ,
  и память процесса копилась бы часами до первой сборки мусора.

## Известные ограничения

- Температура CPU — только AMD Ryzen (Zen) и только с установленным PawnIO и правами администратора.
- Только основная панель задач, только горизонтальная.
- При автоскрытии панели строка появляется/прячется с задержкой до одного обновления.
- Строка — окно поверх панели, а не часть панели: держится над ней программно (см. «Z-порядок»).
