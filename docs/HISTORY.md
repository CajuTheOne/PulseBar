# PulseBar — история и решения

Хроника разработки (октябрь 2026, ноутбук ASUS ROG Zephyrus Duo 16 GX650PY: Ryzen 9 7945HX,
RTX 4090 Laptop + Radeon 610M, 64 ГБ, внешний монитор 3440×1440).

## 13.10.2026 — первая версия

- **Задача:** строка состояния в свободном месте панели задач — загрузка и температура CPU и GPU, загрузка RAM;
  цвета: красный — перегруз, синий/зелёный — норма. Сначала — макет картинкой (`docs/mockup.png`).
- **Макет:** два варианта — A (одна строка) и B (две строки с полосками загрузки); добавлен промежуточный жёлтый цвет.
- **Решения пользователя:** делать оба варианта; настройки по правому клику (переключение вида, пороги);
  программа в `C:\Program Files\AI Tools\`, название на усмотрение — выбрано **PulseBar**; максимально лёгкая;
  запуск вместе с Windows.

### Технические решения

| Вопрос | Отвергнуто | Выбрано | Почему |
|---|---|---|---|
| Температура CPU | LibreHardwareMonitorLib | свой вызов PawnIO (один IOCTL) | у библиотеки 10 зависимостей (HidSharp, System.Management и др.) и опрос всех датчиков |
| Драйвер | WinRing0 | PawnIO (уже был установлен) | WinRing0 блокирует Defender |
| GPU | NVML / nvidia-smi | D3DKMT | без DLL NVIDIA, тот же источник, что у Диспетчера задач, не будит спящую видеокарту |
| Окно | дочернее окно панели задач (`SetParent`) | отдельное окно поверх панели | изоляция: зависание PulseBar не трогает Проводник; нет проблем с правами администратора |
| Автозапуск | ключ Run в реестре | задача Планировщика | запуск с правами администратора без окна UAC; без остановки от батареи |
| Хранение настроек | System.Text.Json | простой ini | не тянуть лишнюю сборку |

- Раскладки структур D3DKMT сверены компиляцией пробной программы на C с заголовками Windows SDK.
- **Производительность:** первая сборка тратила 8 % одного ядра — оказалось, каждый запрос статистики движка GPU
  стоит ~0,5 мс, а движков 14. Опрашиваются только 3D/вычисления и (реже) видеокодеки → 0,39 % ядра, ~18 МБ.
- Установка: UAC в первый раз был отменён, со второго раза установлено. Температура CPU заработала (70 °C).

### Доработки внешнего вида (13.10)

## 16.10.2026

- **VRAM** по аналогии с RAM: занятая собственная память видеокарты (сумма сегментов D3DKMT), процент с цветом по порогу
  и объём в ГБ; блок рядом с GPU; пункт «Show VRAM»; строка в окне порогов (70/85 %). Сверено:
  6099 МБ = счётчик Диспетчера задач, nvidia-smi 6090 МиБ.
- Надпись «vRAM» — попробовали и вернули «VRAM».
- Подпись VRAM уменьшена: в двух строках 10 px (вертикальная), в одной строке — как у всех (11 px).
  Подпись RAM — как у CPU/GPU.
- **Ошибка: падение при правом клике** — «Only the invariant culture is supported in globalization-invariant mode…
  1033 (0x0409) is an invalid culture identifier». Причина: режим `InvariantGlobalization` + WinForms создаёт
  `CultureInfo` по коду раскладки клавиатуры, когда окно становится активным. Воспроизведено и исправлено:
  системный NLS (`System.Globalization.UseNls`), числа форматируются инвариантно («38.4 GB»).
  Необработанные ошибки теперь пишутся в журнал без системного окна «Continue / Quit».
- **Меню моргало** при наведении и нажатии клавиш: строка раз в секунду поднималась на самый верх слоя «поверх всех»
  и перекрывала меню. Теперь встаёт сразу над панелью задач; пока меню открыто — не перерисовывается.
- **Строка пропадала на секунду**, если открыть меню и кликнуть по панели задач: событие смены активного окна
  приходило, пока меню считалось открытым. Теперь строка держится над панелью и при открытом меню, плюс повторная
  проверка через 120 мс. Пользователь подтвердил: больше не пропадает.

## 30.10.2026 — план 2.x и разбор модуля Logitech 1.1.0

- С пользователем согласован план 2.0–2.3 — [PLAN-2.x.md](PLAN-2.x.md).
- Почему в 1.1.0 слетала подсветка, M1 то возвращал её, то нет, а потом клавиатура погасла
  (разбор кода `src\PulseBar\Logi\`):
  - вся подсветка пишется только в RAM клавиатуры (HID++ `0x8081`), во встроенную память ничего не пишется;
  - клавиатура переводится в режим «управляет программа» (`0x8100` fn1 = 2) и **никогда не возвращается** в обычный —
    ни при выходе, ни при ошибке; если кадр подсветки не дошёл, клавиатура остаётся тёмной;
  - после сна подсветка восстанавливается только по событию подключения от приёмника (`0x41`); пробуждение без
    переподключения не замечается, проверка раз в 5 минут повторяет настройку только если устройство «не в сети»;
  - записи не проверяются: куски кадра с таймаутом пропускаются, кадр всё равно фиксируется (в журнале ELLE —
    `per-key paint failed (-1)`); возврат яркости после приглушения — одна попытка без проверки;
  - нажатие M перерисовывает кадр, но не включает заново режим «управляет программа»;
  - два потока чтения без `await` (предупреждения CS4014), один программный id для всех запросов — поздний ответ
    принимается за ответ на следующий запрос; макрос выполняется в потоке чтения и блокирует все ответы до 60 с;
  - G HUB только обнаруживается для предупреждения, обе программы пишут в клавиатуру одновременно.
- Решения для 2.2 — в плане: профили во встроенной памяти, одна очередь HID++, проверка и повтор записей,
  сверка «желаемого состояния» после пробуждения, при выходе — возврат в обычный режим.

### Диагностика G915 (`--logi-diag`, пользователь нажимал клавиши)

Журнал — `tests\PulseBar.Tests\Data\g915-diag-20261031.txt` и `config\ZEFIRKA\`.

- G-клавиши (`0x8010`): маска LE16 (G1 01 … G5 10), удержание — одно событие. MR (`0x8030`): 01 / 00.
  M-клавиши (`0x8020`): маска (M1 01, M2 02, M3 04). Обычные клавиши событий не дают.
- **Причина «M1 → M2» в 2.2:** одно нажатие M1 пришло как 03 → 02 → 03 → 02 → 00 — маленькие соседние M1 и M2
  нажались вместе, 2.2 приняла это за M1 и M2. Теперь из нескольких M в одном сообщении считается только левая.
- **Вторая причина «просто синей»:** запущена служба Logitech LampArray, в Windows включено «Динамическое
  освещение» с цветом акцента (синий #0078D4). Во встроенном режиме после каждой смены профиля клавиатура шлёт
  `0x8071` fn1, и служба перекрашивает клавиши. Ответы на её запросы видны в канале PulseBar: теперь PulseBar
  перерисовывает свой кадр через 0,5 с (не больше 5 раз в минуту) и предупреждает во вкладке, с кнопкой настроек
  «Динамического освещения».
- `0x8071`: зона 0 — логотип (место 2; выкл, статичный, цикл, дыхание), зона 1 — клавиши (место 1; ещё волна,
  рябь, 0x0C). В 2.2 зоны были перепутаны.
- `0x8081` fn0: карта номеров по страницам (0–111 все, затем мультимедиа, G1–G5, логотип) — это номера, которые
  клавиатура принимает, а не её клавиши; список клавиш строится по раскладке `0x4540` (7 — русская, ANSI).
- Кнопка яркости: `0x8040` fn0 [яркость BE16] (25 → 12). Запись лампочек M эха не даёт.

## 31.10.2026 — версия 2.3.0-beta.2 (ZEFIRKA): подсветка пропадала, клавиатура не отпускалась

Пользователь поставил 2.3.0-beta.1 через обновление: сначала всё работало (M1–M3, кнопка яркости), через минуту
«подсветка совсем пропала, не реагирует на M1 M2 M3».

- **Причина 1 — программное управление подсветкой** (`0x8071` fn5): [0] → [0, режим, флаги], [1, режим, флаги] —
  записать. Эффекты из программы (fn1) G915 принимает только при бите 0 режима, иначе ошибка 5. После перехода в режим
  PulseBar было `02 06`, и эффекты отклонялись. Служба Logitech LampArray после смены профиля во встроенном режиме
  ставит `03 06`, и тогда они проходили. Поэтому в бете 1 эффекты то работали, то нет, а ошибка 5 при первой проверке
  была не из-за последнего байта команды. Проверено вызовами `--logi-call`: `02 06` — ошибка 5, `03 06` — эффекты
  приняты, в том числе с последним байтом 0. Теперь PulseBar при настройке ставит бит 0 (флаги оставляет), при
  ошибке 5 ставит его заново и повторяет, при отпускании возвращает прежнее значение. Последний байт эффекта снова 0:
  не сохранять в памяти клавиатуры, без лишних записей во флеш.
- **Причина 2 — клавиатура не отпускалась при закрытии строки.** WM_CLOSE (taskkill, установщик при обновлении)
  закрывает скрытое окно строки без событий формы: `OnFormClosed` не вызывался, клавиатура оставалась в режиме 2 с
  перехваченными G-клавишами, M1–M3 не работали. Теперь клавиатура отпускается и после выхода из цикла сообщений,
  и по WM_ENDSESSION (выключение или выход из Windows). Проверено: после taskkill — режим 1, профиль 1.
- Новый ключ `--logi-call <функция> <fn> [аргументы]`: один запрос HID++ к клавиатуре рядом с работающей строкой,
  ответ — в `%LOCALAPPDATA%\PulseBar\logi-call.txt`. По ошибке при разборе один такой вызов (fn5 [01]) сбросил режим
  в `00 00`; после него было выставлено `03 06`.
- 31 тест: модель G915 отклоняет эффекты без бита 0; новый тест — режим ставится, после сброса службой ставится
  заново, при выходе возвращается.
